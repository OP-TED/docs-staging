ESPD Request

ESPD Request Business Requirements

The ESPD-EDM models the business and information requirements for the ESPD Request transaction based on Directive 2014/24/EU (Article 59) and Regulation (EU) 2016/7.

ESPD Request XSD Schema

The ESPD-EDM uses the UBL-2.4 document named QualificationApplicationRequest.xsd. This schema can be found under the GitHub folder schemas/maindoc.

Figure 1. QualificationApplicationRequest-2.4 main elements.

ESPD Request Cardinalities

The UBL-2.4 Schema is flexible â€” except for in a few cases, all elements are optional. The ESPD-EDM model adds restrictions regarding the cardinalities of some elements.

Figure 2. ESPD-EDM 'QualificationApplicationRequest', UML diagram

The cardinality constraints added by the ESPD are not defined in the XSD Schema. To control these constraints, the ESPD-EDM uses ISO Schematron assertions. The ESPD-EDM distribution package provides Schematron schemata and CVA files for the validation of the XML instances (folder /validation).

For the detailed element-by-element reference with all cardinalities, data types, and business rules, see Request Model Reference.

Lot Management

For details on how lots are managed in the ESPD Request, see Lots Management.

Key points:

  • Exclusion grounds are general â€” they apply to all lots in the procedure.

  • Selection criteria are lot-specific â€” each must reference the applicable lot(s) via cac:ProcurementProjectLotReference.

  • On the Economic Operator’s side, there are as many ESPD Responses as lots the EO tenders for.

EU and Notice Publications

For procurement procedures above the threshold, it is compulsory to reference the Contract Notice published in TED.

The ESPD uses the UBL component cac:AdditionalDocumentReference to include references to relevant documents, including TED and national publications.

Key rules:

  • If the document referenced is a Contract Notice published on TED, the ID must follow the Publications Office format: [][][][]/S [][][]-[][][][][][] (e.g. 2017/S 142-293520).

  • If at the time of drafting the notice has not yet been published, use 0000/S 000-000000 and include the temporary "Received Notice Number" in a second cbc:Description element.

  • Use the Code List DocrefcontentType for cbc:DocumentTypeCode.

For detailed element tables, see Request Model Reference.

Contracting Party

The ESPD expects data about one buyer. In case of joint procurement, the data collected is about the leader of the joint procurement procedure.

The contracting party information will come from eForms, which also uses cac:ContractingParty.

For detailed element tables, see Request Model Reference.

Service Provider

The Buyer may use a Service Provider to manage the publication of the ESPD Request. Service Provider data is optional.

For detailed element tables, see Request Model Reference.
