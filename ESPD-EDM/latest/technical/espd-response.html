ESPD Response

Business Requirements Specification

The ESPD-EDM models the business and information requirements for the ESPD Response transaction in accordance with Directive 2014/24/EU (Article 59) and Regulation (EU) 2016/7. The formal information requirements are defined in the Response Model Reference.

BUSINESS REQUIREMENT

The ESPD Response document must include all the criteria that are present in the ESPD Request. For certain selection criteria the economic operator can add additional properties so it can include more responses than the minimum required by the buyer.

ESPD Response XSD Schema

The ESPD-EDM uses the UBL-2.4 document QualificationApplicationResponse.xsd. This schema is available at ubl-2.4/xsdrt/maindoc.

Figure 1. QualificationApplicationResponse XSD Schema, global view

This section does not cover elements already described in the ESPD Request (such as cac:ContractingParty, cac:ProcurementProject, cac:AdditionalDocumentReference), unless a Response-specific clarification is needed.

ESPD Response Cardinalities

The UBL-2.4 Schema is flexible — most elements are optional. The ESPD-EDM adds cardinality restrictions enforced via ISO Schematron assertions. These can be seen in the diagram below which presents the ESPD-EDM structure for the ESPD Response with its own cardinality restrictions.

Figure 2. ESPD-EDM 'QualificationApplicationResponse', UML diagram

For detailed element tables with all cardinalities, data types, and business rules, see Response Model Reference.

Economic Operator

The economic operator information is spread in two places:

  1. The UBL-2.4 cac:EconomicOperatorParty component (identification, role, party data);

  2. Criteria data structures classified as CRITERION.OTHER.EO_DATA.* (e.g. sheltered workshop, together with others, relied-on entities, subcontractors).

Key requirements

  • One ESPD Response per economic operator — every participant in a tender must provide its own ESPD Response.

  • One ESPD Response per lot — each EO submits a separate response per lot (or group of lots) they tender for.

  • Group name consistency — all economic operators in a group must use the exact same group name spelling.

Roles

The role of the economic operator is specified via cac:EconomicOperatorRole/cbc:RoleCode using code list EoRoleType:

  • Sole tenderer

  • Group leader

  • Group member (not leader)

  • Other entity (relied upon)

  • Subcontractor

For detailed element tables, see Response Model Reference.

Answering QUESTIONs

The ESPD Response uses cac:TenderingCriterionResponse to answer each QUESTION from the Request. Key rules:

  • Each response is linked to one, and only one, criterion property via cbc:ValidatedCriterionPropertyID (matching the UUID from the Request).

  • One response may contain a list of cac:ResponseValue elements of the same type.

  • If confidential, linked evidences must also be treated as confidential.

  • Response data types must match the cbc:ValueDataTypeCode specified by the buyer in the Request.

For the criterion-property-response linking mechanism, see How Criteria Work.

Evidence

Economic operators can reference evidence documents that prove compliance with criteria. Evidence is linked indirectly to responses: cac:EvidenceSupplied/cbc:ID in the response references cac:Evidence/cbc:ID at document level.

Key elements: * cac:Evidence/cbc:ID — unique identifier for the evidence * cac:Evidence/cbc:ConfidentialityLevelCode — access right (PUBLIC, CONFIDENTIAL) * cac:Evidence/cac:DocumentReference — contains the URI, verification code, and issuer

For detailed element tables, see Response Model Reference.

Lot Management in the Response

In the ESPD Response, cac:ProcurementProjectLot under the root element defines which lot(s) the EO is answering for. See Lots Management for full details.

The ESPD Response must include a reference to the ESPD Request that is being responded. The XSD diagram below shows (in blue) which elements are expected for this reference.
