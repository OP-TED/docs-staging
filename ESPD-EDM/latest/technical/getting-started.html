Getting Started

Getting Started with ESPD-EDM Implementation

The ESPD Exchange Data Model (ESPD-EDM) assists developers in building ESPD Services. It provides a model that ensures the ESPD Request and ESPD Response XML files produced across all services are consistent and comply with EU procurement legislation.

Architecture Overview

Figure 1. ESPD Architecture Overview

The architecture components interact to produce the ESPD UBL XML Request and Response documents:

  • UBL (Universal Business Language) — defines the XML elements and attributes used in ESPD documents. ESPD-EDM v5.0.0 uses UBL 2.4.

  • UML Model — describes the Request and Response model elements, their attributes, relationships, and cardinalities. Maintained in Enterprise Architect.

  • Criterion Data Structure (JSON) — defines each criterion and its hierarchical tree of properties. Created as a JSON file (espd-edm.json) extracted from Enterprise Architect.

  • ESPD UBL XML — the resulting ESPD Request and Response XML files, generated by XSLT transformations applied to the criterion data.

  • Code Lists (Genericode) — attribute-value structure of codes for each code list, distributed as .gc files. Metadata is defined in codelists.json.

  • Validation (Schematron) — validates generated ESPD XML files against UBL schema and ESPD-specific business rules.

Key Standards

Standard Role in ESPD-EDM

UBL 2.4

Base XML schema. ESPD uses QualificationApplicationRequest and QualificationApplicationResponse document types.

ISO Schematron

Rule-based validation of ESPD XML instances beyond what XSD can enforce.

Genericode 1.0

Format for distributing code lists used in ESPD documents.

XSLT 3.0

Transformation language used to generate ESPD XML from criterion data and to compile Schematron into executable XSL.

Distribution Package

The ESPD-EDM distribution package is available at GitHub. It contains:

Folder Contents

codelists/

Genericode (.gc) files for all code lists + codelists.json metadata reference.

criterion/

Criterion definitions in JSON format (espd-edm.json) + JSON schema for validation.

ubl-2.4/

Official UBL 2.4 distribution files from OASIS.

validation/

Schematron source files (.sch) and compiled XSL files for ESPD Request and Response validation.

xml-examples/

Sample ESPD Request and Response XML documents.

For more details on the distribution package, see Distribution Package.

Repository Structure

The ESPD-EDM project uses several GitHub repositories:

Repository Purpose

OP-TED/ESPD-EDM

Main repository: UBL schemas, code lists, criterion data, validation artefacts, XML examples.

OP-TED/espd-docs

This documentation (Antora-based).

OP-TED/espd-validation-schematron

Schematron source files for ESPD business rules validation.
