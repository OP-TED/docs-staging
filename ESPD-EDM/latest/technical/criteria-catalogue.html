Criteria Catalogue

Criterion Elements Reference

This section provides the detailed element-by-element reference tables for criterion components.

XSD Schema Overview

This XSD Schema diagram shows a global view of the UBL 2.4 cac:TenderingCriterion component:

Figure 1. cac:TenderingCriterion - XSD Schema, global view

Criterion (cac:TenderingCriterion)

Class name: cac:TenderingCriterion

Definition:

A tendering criterion describes a fact or a condition that is used by the buyer to evaluate and compare tenders by economic operators and which will be used for the exclusion and the selection of candidate tenderers to the award decision.

Business rule(s):

BR-LOT-20, BR-LOT-30, BR-LOT-30-S20, Common (BR-TC-01)

File:

os-UBL-2.4/xsdrt/common/UBL-CommonAggregateComponents-2.4.xsd

Path:

/QualificationApplicationRequest/cac:TenderingCriterion
Components Type Card Description Requirements

cbc:ID

Identifier

1

A language-independent token that allows to identify a criterion uniquely.

Rule: Each Criterion is defined in e-Certis and must use the UUID supplied by e-Certis. See also espd-edm.json.

cbc:CriterionTypeCode

Code

1

A classification code defined by the ESPD-EDM to represent the criterion in the ESPD taxonomy.

Rule: Compulsory use of codes from e-Certis (e.g. crime-org, corruption, chain-manage).

cbc:Name

Text

1

A short and descriptive name for a criterion.

Rule: The name should match the one from e-Certis.

cbc:Description

Text

1..n

An extended description of the criterion.

Rule: The description should match the one from e-Certis.

cac:ProcurementProjectLotReference

Class

0..n

One or more procurement project lots to which this criterion relates.

Rule: Mandatory for all Selection Criteria (1..n). Not necessary for exclusion grounds.

See Lots Management.

cac:SubTenderingCriterion

Class

0..n

Descendant criteria used to define national exclusion criteria that specialise EU criteria.

Rule: A sub-criterion 'is a' criterion.

cac:Legislation

Class

0..n

A reference to the legislation related to the Criterion.

See Legislation (cac:Legislation) below.

cac:TenderingCriterionPropertyGroup

Class

1..n

The first level group of properties and sub-groups of properties.

Legislation (cac:Legislation)

The XSD schema below shows, in blue, the elements of the component cac:Legislation used to point at the legislation related to the criterion.

Figure 2. cac:Legislation XSD Schema

Components Type Card Description Requirements

cbc:ID

Identifier

0..1

An identifier to refer to the legislation.

cbc:Title

Text

1..n

Title of the legislation.

Rule: The complete title as in the original legal text.

cbc:Description

Text

0..n

Textual short description of the legislation.

cbc:JurisdictionLevel

Text

0..n

Jurisdictional level (e.g. "EU Directive").

cbc:Article

Text

0..n

The article of the legislation.

cbc:URI

Identifier

0..1

URI pointing to the legislation.

Rule: For European legislation, the URL MUST point to the multilingual EUR-LEX web-page.

Property Group (cac:TenderingCriterionPropertyGroup)

Components Type Card Description Requirements

cbc:ID

Identifier

1

Identifies a group of requirements uniquely.

Rule: Compulsory use of the UUIDs supplied by e-Certis.

cbc:PropertyGroupTypeCode

Code

1

Code to control group behaviour (ON*, ONTRUE, ONFALSE).

Rule: Compulsory use of the Code List PropertyGroupType.

cac:TenderingCriterionProperty

Class

1..n

Caption, requirement or question.

See Property (cac:TenderingCriterionProperty) below.

cac:SubsidiaryTenderingCriterionPropertyGroup

Class

0..n

Second/third/n-level sub-group inside a first level group.

Rule: Subsidiary property groups 'are' property groups — same rules apply.

Property (cac:TenderingCriterionProperty)

Components Type Card Description Requirements

cbc:ID

Identifier

1

Identifies one specific property.

Rule: UUID version 4 numbers, automatically generated. Responses reference this UUID.

cbc:Description

Text

1

The text of the caption, requirement or question.

cbc:TypeCode

Code

1

The type of property (CAPTION, REQUIREMENT, QUESTION).

Rule: Use code list CriterionElementType. If CAPTION or REQUIREMENT, then cbc:ValueDataTypeCode must be NONE.

cbc:ValueDataTypeCode

Code

1

The type of answer expected by the buyer.

Rule: Use code list ResponseDataType. Must be different from NONE for QUESTION properties.

cbc:ValueUnitCode

Code

0..1

Unit of measure for numeric responses.

cbc:ValueCurrencyCode

Code

0..1

Currency for amount responses.

cbc:ExpectedAmount

Amount

0..1

The amount in the expected response.

cbc:ExpectedID

Identifier

0..1

Expected identifier (e.g. Lot ID).

cbc:ExpectedCode

Code

0..1

Expected code value.

cbc:ExpectedValueNumeric

Numeric

0..1

Expected numeric value.

cbc:ExpectedDescription

Text

0..1

Description of expected evidence.

cbc:MaximumValueNumeric

Numeric

0..1

Maximum value the response must have.

cbc:MinimumValueNumeric

Numeric

0..1

Minimum value the response must have.

cbc:CertificationLevelDescription

Text

0..1

Description of expected certification level.

cac:ApplicablePeriod

Class

0..1

The period to which this criterion property applies.

Rule: Only start date and end date expected.

cac:TemplateEvidence

Class

0..n

Pointer to evidence supporting this criterion.

Data Structure Vocabulary

The ESPD-EDM data structure vocabulary maps to UBL-2.4 elements as follows:

ESPD-EDM Vocabulary UBL-2.4 Element

CRITERION

cac:TenderingCriterion

SUBCRITERION

cac:SubTenderingCriterion

REQUIREMENT_GROUP

cac:TenderingCriterionPropertyGroup

QUESTION_GROUP

cac:TenderingCriterionPropertyGroup

REQUIREMENT_SUBGROUP

cac:SubsidiaryTenderingCriterionPropertyGroup

QUESTION_SUBGROUP

cac:SubsidiaryTenderingCriterionPropertyGroup

CAPTION

cac:TenderingCriterionProperty (TypeCode=CAPTION)

REQUIREMENT

cac:TenderingCriterionProperty (TypeCode=REQUIREMENT)

QUESTION

cac:TenderingCriterionProperty (TypeCode=QUESTION)

ADDITIONAL_DESCRIPTION_LINE

cbc:Description (in cac:TenderingCriterion)

LEGISLATION

cac:Legislation

The vocabulary is defined in the code list CriterionElementType.

Criterion Data Source

Starting with ESPD-EDM v5.0.0, criterion definitions are maintained in JSON format (espd-edm.json), replacing the deprecated Excel-based workflow. See Distribution and Tooling for details on the JSON data model.
